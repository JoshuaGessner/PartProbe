# Public Synthetic Fixtures

These fixtures are deliberately simple and contain no customer or shop data. They bootstrap the test harness; they do not validate production CAD coverage.

- `models/cube_10mm_ascii.stl`: closed triangular cube, unitless by STL definition; fixture convention proposes millimetres but import must require/record confirmation.
- `models/cube_10mm_binary.stl`: deterministic binary encoding of the same governed cube, reproduced from the ASCII source by `scripts/generate_binary_stl_fixture.py`; it carries the same unit uncertainty.
- `models/adversarial_binary_stl_*.stl`: four deterministic rejected derivatives covering a truncated final triangle record, unsupported nonzero per-facet attribute data, a non-finite normal component, and triangle-count quota overflow; reproduced by the same binary-STL script.
- `models/adversarial_ascii_stl_*.stl`: four deterministic rejected byte streams covering invalid UTF-8, malformed facet grammar, an empty solid, and one collinear degenerate triangle; reproduced by `scripts/generate_ascii_stl_adversarial_fixtures.py`.
- `models/open_cube_10mm_ascii.stl`: same cube with one face missing, intended to trigger non-watertight/open-boundary diagnostics.
- `models/self_intersecting_tetrahedra_ascii.stl`: project-authored analytic ASCII STL with two individually closed/wound tetrahedral shells whose surfaces intersect; the exact-predicate comparison detects the intersection, holds confidence at `NeedsReview`, and withholds enclosed volume/centroid.
- `models/cube_1cm_translated.3mf`: deterministic 3MF Core/OPC package derived from the governed cube, with explicit centimetre units and one build translation to `(20, 30, 40)` mm; reproduced by `scripts/generate_3mf_fixture.py`.
- `models/cube_1cm_component_scaled_translated.3mf`: deterministic variant that references the mesh through one component object, applies a positive-determinant component scale/translation, then applies a build translation; reproduced by the same script.
- `models/cube_1cm_nested_component_chain.3mf`: deterministic variant with two strictly linear component references and ordered positive-determinant transforms before the build translation; reproduced by the same script.
- `models/adversarial_3mf_*.3mf`: twenty-one deterministic rejected packages covering graph/reference/union/metadata/material/extension/archive threats, malformed model XML, a forbidden document type, and archive entry-count overflow; reproduced by the same script. The backslash-name case is constructed by equal-length raw ZIP filename rewriting so its bytes do not depend on the host path separator.
- `models/cube_10mm_3mf_{micron,millimeter,meter,inch,foot,default_mm}.3mf`: deterministic direct-mesh unit corpus. Together with the explicit-centimetre fixture, these persist all six Core unit declarations plus the normative millimetre default while preserving identical canonical 10 mm geometry.
- `models/cube_10mm_3mf_metadata.3mf`: deterministic explicit-millimetre cube with three public well-known Core model metadata entries. Analysis retains only entry/preservation counts and a not-interpreted warning, never metadata names or values.
- `expected/cube_10mm.json`: reviewed mathematical expectations and tolerances, not parser output.
- `expected/cube_10mm_binary.json`: the separately identified binary-encoding expectation with the same analytic geometry.
- `expected/cube_1cm_translated_3mf.json`: canonical-millimetre expectations proving declared-unit conversion and build-transform application.
- `expected/cube_1cm_component_scaled_translated_3mf.json`: analytic 20 × 10 × 10 mm expectations proving component-then-build transform order and retained component provenance.
- `expected/cube_1cm_nested_component_chain_3mf.json`: analytic 20 × 30 × 10 mm expectations proving ordered leaf-to-build application and retention of both component links.
- `expected/cube_10mm_3mf_*.json`: separate fixture identities and canonical 10 mm expectations for each persisted unit/default package; the shared geometry does not make these independent shape fixtures.
- `expected/cube_10mm_3mf_metadata.json`: canonical cube evidence plus the required metadata-not-interpreted warning for `FIX-MESH-012`.
- `expected/self_intersecting_tetrahedra.json`: schema-v3 expected measurements, self-intersection state, categorical confidence/reasons, and unavailable closed measurements for `FIX-MESH-039`.
- `expected/adversarial_3mf_*_rejection.json`, `expected/adversarial_binary_stl_*_rejection.json`, and `expected/adversarial_ascii_stl_*_rejection.json`: typed schema-v1 recoverable-failure expectations for `FIX-MESH-014`–`038` and `FIX-MESH-040`–`043`; each pins the source hash and sanitized diagnostic and forbids a geometry snapshot/output or retained staged input.

The bounded ASCII/binary STL comparison analyzers reproduce source-coordinate triangle, bounds, area, closure, winding, self-intersection, and categorical confidence evidence while deliberately leaving STL units unresolved. The bounded 3MF comparison analyzer validates the package relationship/content-type path, inspects raw ZIP entry policy before decompression, applies explicit archive/XML/entity/compression/object/component/model-metadata limits, converts every Core unit declaration or normative default into canonical millimetres, and accepts one direct mesh or a strictly linear bounded chain in which each component object references the immediately preceding object exactly once. It retains and applies the ordered chain before the build transform. Well-known unprefixed model metadata is counted and warned but never retained or interpreted. Both paths expose enclosed volume/centroid only for closed, consistently wound geometry with self-intersection `not_detected`. Mesh confidence never exceeds `Low`; unresolved units, topology defects, detected intersection, or indeterminate coplanar overlap require `NeedsReview`. The persisted adversarial corpus proves exact fail-closed behavior for twenty-one selected 3MF graph/structure/metadata/extension/package/XML/resource layouts, four malformed binary STL layouts, and four invalid ASCII STL byte/grammar/geometry cases; supported general component DAGs, material interpretation, reflected/singular-transform packages, broader representative malformed entity/geometry cases, and alternate legal packages still need coverage. The exact-predicate intersection result is not a reviewed production tolerance/welding policy. This is synthetic parser evidence, not a supported importer or worker/desktop acceptance.

Successful expectation schema v3 requires explicit mesh self-intersection state and categorical confidence/reasons, forbids mesh confidence above `Low`, and forbids enclosed volume/centroid for a self-intersecting mesh. Earlier successful schema versions are not inferred or silently upgraded; the separate failure schema remains v1.

`manifest.yaml` is authoritative for fixture provenance, hashes, classification, parser/detector/policy versions, limits, and expected-result files. Project redistribution licensing, domain-expert review, production intersection/welding tolerance, broader representative malformed entity/geometry cases, general 3MF DAG/material/package coverage, and representative machining parts remain required; do not manufacture questionable hand-written fixtures and call them representative.
