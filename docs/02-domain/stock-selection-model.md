# Stock Selection Model

> **Status:** Draft  
> **Last updated:** 2026-09-15
> **Related requirements:** REQ-F-005; GEO-008; CALC-002–CALC-007  
> **Related ADRs:** ADR-0002, ADR-0004  
> **Open questions:** OQ-009, OQ-010  
> **Dependencies:** Geometry and material models  
> **Supersedes:** None

Candidate stock forms: rectangular bar, plate, round, tube/pipe, hex, sheet, forging, casting, customer-supplied, near-net, and custom preform. A candidate stores source size, orientation, dimensional allowances, supplier evidence, yield/nesting method, certifications, restrictions, lead time, cost, risk, confidence, and rejection reasons.

Ranking considers enclosure, candidate orientation, saw/facing/workholding/clamp allowances, standard sizes, kerf, remnant policy, minimum order, availability, grain direction, country-of-origin constraints, material risk, and outside blanking. It returns alternatives—not one hidden optimum. The estimator can choose or define stock and must see mass, removed volume, cost, and risk deltas.

USE-2 schema v2 now persists one optional draft `StockAllowanceProfile` with a versioned rectangular, round, or plate form and explicit nonnegative X/Y/Z millimetre allowances plus source evidence. It is configuration input for the future USE-3 proposal rule, not a selected blank, stock-volume result, automatic recommendation, or production default.

The `shop-resource-catalog-v1` contract can retain bounded exact stock-allowance versions and pin one in a reviewed resource selection. Schema v3 persists that evidence and schema v4 can persist the separate authorization decision. The draft service preserves current allowance evidence, permits only correctly versioned Draft additions/successors, and downgrades active proposal eligibility on edit; the separate catalog application can create a policy-evaluated and audit-gated active-for-proposals successor. Contract v9 maps the complete bounded draft through native identity/time evidence, but ordinary startup remains identity-unavailable and the WebView exposes no catalog action. An application proposal resolver may consider the pinned allowance only when the controlled exact STEP envelope is present; it does not authorize estimate adoption. A governed editor, authenticated identity/roles, a reviewed shipped allow configuration, and activation UI remain pending.

## USE-3 rectangular envelope policy v1

`partprobe-rectangular-stock-envelope-policy` v1.0.0 is the first pure proposal rule. Geometry-core defines additive exact STEP envelope derivative schema v1 with positive source-axis AABB extents in canonical millimetres and the authorized source hash. `geometry-step-analysis-v1` carries that derivative beside the complete unchanged `geometry-snapshot-v1`; the controlled-output hash remains supervisor-owned. Native OCCT adapter ABI v4 measures those extents with precise B-rep bounds, triangulation disabled, and shape-tolerance inflation disabled; the worker emits the container. Setup-planner converts the validated pair into source/output-bound proposal evidence only when the exact snapshot contains one solid body.

The rule requires an exact `active_for_proposals` selection that pins the supplied stock-allowance identity/version. The allowance record must be `Reviewed` or `Approved` and its form must be `Rectangular`. Each stored X/Y/Z allowance is the **total dimensional addition on that axis**, not a per-side value:

`blank_x = extent_x + allowance_x`; `blank_y = extent_y + allowance_y`; `blank_z = extent_z + allowance_z`.

`blank_volume = blank_x × blank_y × blank_z`; `removed_volume = blank_volume − exact_part_volume`. All arithmetic is checked and impossible negative removal fails visibly. The proposal remains categorical `NeedsReview` because v1 evaluates only the source-axis orientation and resolves neither standard stock size nor current availability. It does not select material, calculate price, adopt an estimate input, reserve stock, or authorize purchasing/production.

This is a new non-persisted proposal/evidence contract, so no historical estimate or database migration applies. Any change to allowance interpretation, enclosure, orientation, arithmetic, eligibility, or reason codes requires a new rule/evidence version plus an explicit migration/replay decision and updated analytic fixtures. Validation evidence is in [USE-3 stock proposal validation](../06-quality/use-3-stock-proposal-validation.md).

`ExactStepStockProposalApplication` is the first application resolution boundary. It accepts analyzed geometry plus a validated shop catalog, requires the catalog's one exact active-for-proposals selection, resolves its pinned allowance version, and returns the rule result without mutation. Legacy STEP output with no derivative, mesh evidence, or a catalog with no active selection remains `Unavailable`; invalid or inapplicable controlled evidence remains `Blocked`. This is review-state resolution only—not proposal adoption, estimator confirmation, material purchasing, calculation authority, or quote approval.

For the internal live-test bridge, `partprobe-developer-estimate-input-proposal` v1.0.0 consumes the same controlled one-solid exact STEP envelope plus one exact persisted schema-v2 starter-library draft. It preserves the draft lifecycle and pins the source/output, library, material, offer, allowance, machine, and runtime identities and versions. It derives the source-axis rectangular blank, removed volume, density-converted blank mass, exact unrounded unit stock material cost, and coarse setup/programming/volumetric-cutting/load/quality times. Milling and machine-envelope compatibility are required. The result is always session-only `NeedsReview`; it is not catalog activation, CAM, a standard-size/availability result, or estimate authority.

`partprobe-developer-estimate-proposal-adoption` v1.0.0 is the separate explicit application boundary for the internal coarse estimate. It requires the exact settings revision/library version, two affirmative review decisions, quantity, native actor/time, and a bounded reason. It calculates total purchased stock material from unit blank cost and make quantity. Non-cutting/in-cycle inspection, cut/cert/freight, tooling/fixture/outside processing, administration/overhead, and risk/rework are excluded as exact zero only after the estimator explicitly accepts that limitation; the output trace lists those exclusions. Re-analysis or a changed settings/library version makes the displayed proposal stale. The adoption remains session-only, unapproved, and not a quote.

## VIS-4 developer stock candidate rule v1

`partprobe-developer-stock-candidate` v1.0.0 introduces a distinct, nonserializable, session-only candidate evidence contract (schema v1), not a modification of the original proposal/adoption rules. The initial edit input is final X/Y/Z blank size in canonical millimetres. Every dimension must be positive and at least the exact one-solid STEP source-axis extent, with no rotation or implicit tolerance. It may reduce the original allowance to zero, but that is an explicit review-required override, never an approved machining allowance. The unchanged pinned milling-machine envelope must enclose the edited blank on corresponding axes. Equal-to-current dimensions are rejected as no change.

The rule reuses the original checked stock-dependent arithmetic: `blank_volume = x × y × z`; `removed_volume = blank_volume − part_volume` (negative fails, never clamps); `blank_mass_kg = blank_volume × density_kg_per_m3 / 1,000,000,000`; `unit_stock_material_cost = blank_mass_kg × price_per_kg`; `cutting_minutes = removed_volume / removal_rate_mm3_per_minute`. All intermediate values must be exactly representable; overflow or division requiring an unconfigured rounding policy fails visibly. Setup, programming, load/unload, and quality times remain pinned unchanged. Total allowances are the edited blank dimensions minus model extents, not per-side additions.

Revision one retains the complete original proposal, exact envelope/source/analysis-output binding, complete settings snapshot (including profile/revision, library and all child versions/evidence), original and new blank dimensions, candidate identity, actor, time, and a nonempty bounded reason. A successor preserves the original basis and identity, increments the revision exactly once, records the predecessor revision and immediately previous dimensions, and requires exact normalized typed current settings/envelope evidence; changed source, output, geometry, settings, rates, pricing, library, or child evidence is stale even if identifiers are reused. It does not retain a recursively growing history inside each value: the future application must retain immutable revisions and enforce optimistic session sequencing. Pure value construction is not authorization, durable audit, concurrency enforcement, review, or adoption.

Every candidate remains categorical `NeedsReview`, inherits all original proposal limitations, and explicitly identifies the edited blank/allowance override. Standard size, availability, workholding, orientation, detailed runtime, purchasing, and CAM remain unresolved. No UI command, estimate-adoption mapping, renderer placement, geometry snapshot, historical estimate, persistence schema, or original v1 proposal is changed. This additive rule applies only to new candidates; no migration/recalculation of existing records occurs. Desktop activation and adoption require later separately versioned application/contract evidence and an explicit review of the exact candidate revision.
