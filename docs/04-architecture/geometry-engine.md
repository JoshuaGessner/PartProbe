## Architecture

The target geometry engine is a UI-independent application service backed by an isolated, partially OS-contained `geometry-worker`. The desktop process submits a content-addressed asset and job options; it receives provisional geometry evidence through a typed application service. The UI never links directly to a geometry kernel, and the kernel never writes quote data. The current GUI-5 client is session-only, has no display-mesh output, and the worker is not an operating-system sandbox.

```text
desktop UI ── application service ── job store / snapshot repository
                                      │
                                      ▼
                             geometry-worker process
 intake → hash → identify → units → parse → heal? → validate → measure
                         → orient → stock → feature job → tessellate
                                      │
                         versioned results / controlled derivative store
```

## Developer native runtime boundary

The evidenced Apple-Silicon and Ubuntu-x86_64 developer paths may assemble the exact native worker, the pinned OCCT version header, the complete installed `TK*` shared-library closure, and the OCCT construction manifest into one explicit runtime root. The same fail-closed contract is implemented for Windows x64 pending configured-native run completion: `.lib` files remain build inputs only, fingerprints cover installed DLL bytes, and the complete `TK*.dll` closure is copied beside the worker in `bin` so verified app-local libraries win the normal loader order. `scripts/assemble_native_runtime.py` accepts only explicit worker, install, construction-manifest, and new output paths. Its schema-v1 manifest records the pinned source policy, host OS/architecture, install fingerprint, relative launch configuration, and the size/hash of every regular file plus the local target of every retained library symlink. Verification rejects traversal, absolute artifact paths, missing, changed, repeated, extra, or escaping artifacts. Assembly validates the copied root before atomically publishing it and never overwrites an existing output.

This runtime root removes the mutable shared-Cargo-output hazard and gives developers a repeatable local launch unit. `crates/native-runtime` repeats the same bounded manifest/artifact/provenance/host checks inside the desktop process before launch and derives the worker and native-library paths only from that verified manifest. Deployment therefore supplies one runtime root plus an external controlled workspace; there is no independent launch-path override or ambient discovery. On Linux, `scripts/verify_native_runtime_links.py` rejects unresolved dependencies or any `libTK*` binding outside the verified runtime. On Windows, construction pins OCCT's supported `INSTALL_DIR_BIN`, `INSTALL_DIR_LIB`, and `INSTALL_DIR_INCLUDE` variables to the canonical PartProbe root; the post-assembly audit requires an explicit `dumpbin.exe`, verifies every worker/DLL is x64, and rejects any imported `TK*.dll` absent from the manifest-bound app-local closure. Header and dependency modes are invoked separately so each strict parser consumes one documented output grammar. The bridge enables MSVC `/EHsc` for its existing caught-exception boundary and uses an explicitly bounded portable diagnostic copy. Native test and desktop launch paths put only the verified Windows `bin` directory in the otherwise-cleared child `PATH`; Unix targets use `lib`. This is not an application installer, bundled MSVC runtime, security signature, immutable store, SBOM, legal approval, or redistribution package, and verification does not prevent post-check mutation. Run 31609710986 proves Windows native tests and runtime assembly/re-verification, but configured Windows PE closure and host-launch evidence remain pending after its mixed-mode parser failure; Linux still requires final window/package evidence before cross-platform packaging claims.

## Pipeline and contracts

| Stage | Inputs / output | Failure and audit behavior |
|---|---|---|
| Intake and hash | controlled file descriptor/path → SHA-256, byte count, MIME/sniff result | reject unreadable, size-limited and mismatched files; preserve no unchecked external reference |
| Identify / parse | bytes + declared extension → format report / neutral representation | parser errors are recoverable diagnostics; extension is not authority |
| Unit resolution | declared format unit, geometry scale signals, user choice → canonical-mm transform | unknown/ambiguous unit is `needs_user_input`; do not compute approval-grade measures |
| Healing (optional) | imported representation → derivative + action log | no in-place mutation; original and derivative hashes, configuration, topology-change warning |
| Validation | representation → exact-solid or mesh report | distinguish invalid, unknown, and not-applicable; preserve partial preview where safe |
| Basic properties | validated representation + transform → measurements | tag exact vs approximate mesh derivation and tolerance |
| Orient / stock | measurements + candidate axes → ranked envelope candidates | proposals only, include clamp/saw/facing assumptions and alternatives |
| Feature extraction | snapshot ref → `FeatureAnalysisSnapshot` | separate job/version; failure cannot invalidate base measurements |
| Tessellation | geometry ref + visual tolerance → display mesh | visual mesh never replaces analysis geometry |
| Snapshot | all outcomes → immutable record | store stage timing, versions, warnings, safe diagnostics and user decisions |

## Process and API boundary

The current transport uses bounded newline-framed JSON on worker stdin and one bounded JSON response on stdout. Control-stream schema version 2 requires an `execute` frame carrying request schema version 1 plus asset-transport manifest schema version 2; a later identity-bound `cancel` frame is optional. The supervisor atomically creates a private per-job directory beneath its configured controlled root, launches the executable there with a cleared inherited environment, polls cancellation and wall time, kills and reaps failed workers, and verifies schema, job, and correlation identity before accepting a response. Unix job directories use owner-only mode; Windows inherits the configured root's access-control list. No unrestricted source path, raw CAD content, database credential, or renderer handle enters JSON. A direct manifest carries exactly one process-local numeric resource ID; verified-copy manifests require that field to be absent.

The supervisor accepts a consumed `AssetReadGrant` that binds one opaque capability to one already-open, nonempty regular-file handle and captures its authorized byte length. It never reopens the source pathname: it verifies the request capability, rewinds and reads the same handle, and rejects length drift, oversize, or hash mismatch. For `verified_private_copy`, it copies verified bytes to the create-new fixed worker-local name `partprobe-input.asset`, marks the file read-only, and sends a path-free manifest. For Unix direct transport, the platform adapter atomically creates a close-on-exec duplicate, clears close-on-exec only for that descriptor in the child, and marks every other non-stdio descriptor close-on-exec before `exec`; the manifest binds its numeric descriptor ID. For Windows direct transport, the platform adapter duplicates the source as inheritable, holds the PartProbe direct-launch mutex through process creation, and uses `STARTUPINFOEXW` plus `PROC_THREAD_ATTRIBUTE_HANDLE_LIST` to inherit exactly child stdin, child stdout, null stderr, and that source HANDLE. Parent pipe ends are non-inheritable, `lpApplicationName` is explicit, the command line is writable and quoted, the Unicode environment is explicitly cleared or contains only the configured native-library `PATH`, and the working directory is explicit. The parent drops child-only and source duplicates immediately after spawn. In both direct modes the worker validates and claims the manifest resource exactly once, disables descendant inheritance immediately, and rechecks all binding fields, regular-file type, exact length, quota, and hash into immutable bytes before adapter dispatch. Native adapters cannot substitute or reopen an arbitrary source path. The supervisor removes any copy and the private directory on every handled completion/failure path.

The low-level local-source opener opens read-only and protects the final path component: Unix uses `O_NOFOLLOW`; Windows opens the reparse point itself, rejects the reparse-point attribute, and requests identification-only security quality of service. This closes the source pathname-reopen window and supports intentional operation after the source pathname is deleted. The application service must still authorize the selected path and safely resolve and contain parent components.

| Platform-neutral policy | Theoretical capability | Current implementation | Deployment behavior |
|---|---|---|---|
| `VerifiedCopyOnly` | Private verified copy on every target | `verified_private_copy` on Windows, Linux, and macOS | Explicitly selected; never labeled direct |
| `PreferDirect` | Unix descriptor or Windows HANDLE through an exact allowlist | `unix_descriptor` on Unix; `windows_handle` on Windows | No copy fallback on implemented Unix/Windows targets; any future unsupported target records the fallback reason |
| `RequireDirect` | Exact allowlisted descriptor/HANDLE only | `unix_descriptor` on Unix; `windows_handle` on Windows | No silent copy; a target without a reviewed direct adapter fails closed |

The `platform` crate isolates both launch mechanisms behind `WorkerCommand`/`WorkerChild`: standard launches retain `std::process`, Unix direct launches add the descriptor allowlist, and Windows direct launches use the audited Win32 process adapter because stable `std::process::Command` cannot attach the required handle-list attribute. The Windows child wrapper preserves stdin/stdout ownership, nonblocking exit observation, termination, wait, and reap semantics. One recursive test per OS family proves the intended source survives while an unrelated inheritable descriptor/event does not; the Windows child cannot signal the excluded event and the parent proves it remains unsignaled. Theoretical OS capability, implemented support, and configured deployment mode remain distinct.

Microsoft's contract requires every HANDLE in the list to be inheritable and `bInheritHandles` to be true while limiting the child to the listed set; PartProbe keeps the list storage and HANDLE array alive through `CreateProcessW`. [UpdateProcThreadAttribute](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute) · [CreateProcessW](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw)

When a validated response carries a snapshot reference, the supervisor opens `partprobe-output.json` with the same final-component no-follow policy, requires a nonempty regular file within the request's output quota, copies exactly that length into immutable supervisor-owned memory while computing SHA-256, binds the bytes/hash/length to the opaque reference, removes the worker-visible path, and deletes the private job directory. An output without a response reference is removed rather than exposed; the response status continues to distinguish successful, partial, and failed evidence. This is bounded spike ownership, not persistence: the controlled derivative store must durably write, classify, authorize, retain, and audit an accepted artifact before it becomes a repository record.

The reversible spike now uses a bounded, newline-framed control stream with its own schema version. The first frame is `execute`; a later `cancel` frame carries the running job/correlation identity plus `user_requested` or `deadline_exceeded`. The supervisor requires an explicit nonzero grace interval, accepts cooperative cancellation only when the worker returns the matching sanitized outcome plus `WORKER_CANCELLATION_ACKNOWLEDGED`, and rejects missing/mismatched acknowledgement as malformed. A fully validated completion may win a cancellation race; a process still alive after grace is killed and reaped with a distinct user-cancel or deadline force-termination code.

Native adapter ABI version 3 passes verified bytes by pointer and length to `STEPControl_Reader::ReadStream` under a fixed non-sensitive auxiliary name and passes the worker's atomic cancellation probe into an OCCT `Message_ProgressIndicator`. OCCT 8.0 polls `UserBreak()` during STEP root transfer, so a validated cancel can stop that phase and return the sanitized `OCCT_CANCELLED` boundary code; Rust contains probe panics and treats them as cancellation rather than unwinding through C++. Stream parsing and `SurfaceProperties`/`VolumeProperties` do not expose progress ranges, so they remain uninterruptible internally. The supervisor's grace-bounded kill/reap path remains the required bound for those phases and for any native code that stops polling.

The supervisor treats launch, protocol I/O, worker exit, timeout, quota breach, malformed response, output-claim failure, cleanup failure, parser-containment setup failure, or cancellation as sanitized failure. Current partial resource containment includes Unix CPU/regular-file/core limits and process-group cleanup, Linux address-space limits, and a suspended Windows Job with per-process CPU, committed-memory, one-process, and kill-on-close controls. On Linux `x86_64`/`aarch64`, the worker sets irreversible `no_new_privs` before creating its cancellation reader, claims and hashes the authorized asset into immutable bytes, and then installs a seccomp classic-BPF filter across the whole thread group with `TSYNC`. The parser phase cannot create sockets, `io_uring`, processes/threads, or execute another image; setup failure returns only `WORKER_CONTAINMENT_FAILED`. This deliberately narrow syscall boundary does not restrict general file opens. Ubuntu 24.04 x86_64 run 31555774851 proves the pinned native OCCT adapter and configured desktop-host smoke remain functional under it; Linux aarch64 native compatibility is not yet evidenced. On every target, each process poll and the post-exit boundary also inspect the private job directory without accepting links, special files, or nested directories; the verified-copy input must remain the same length and read-only, while all other regular files share the request's output-byte budget and a fixed 64-entry ceiling. A violation terminates and reaps a live child, returns `WORKSPACE_OUTPUT_LIMIT_EXCEEDED`, and recursively removes only the supervisor-created job directory, including unclaimed scratch files.

That inspection closes the demonstrated multi-file aggregate-output gap only at supervisor polling boundaries. It is not an OS-enforced storage quota: a hostile process can transiently overshoot or write and remove bytes between polls, and the worker is not prevented from attempting paths outside its job directory. The target design still requires macOS/Windows parser egress denial, OS-enforced filesystem confinement/temporary-storage isolation and hard storage quotas, hard macOS memory enforcement, hostile macOS descendant escape prevention, Linux-aarch64 native-filter compatibility, and derivative cleanup under retention policy. A private directory, cleared environment, controlled working root, Linux parser syscall filter, polling monitor, and these partial limits are defense in depth, not an OS sandbox.

## Kernel adapter boundary

`geometry-core` owns neutral types, units, measurement/validation rules, and pure algorithms. `geometry-import` owns format sniffing and worker protocol. `geometry-occt-adapter` owns all C++ calls, allocation/lifetime conversion and translation/healing reports. `mesh-analysis` owns mesh validation and approximate properties. No domain crate imports OCCT or a renderer. This keeps a commercial replacement possible and confines unsafe FFI; Rust identifies FFI declarations as unsafe. [Rust `extern`](https://doc.rust-lang.org/std/keyword.extern.html)

## Performance and reliability expectations

Stream or preflight inputs where format permits; apply configured byte, entity/triangle, archive-expansion, recursion, CPU, memory, and wall-clock quotas. Cache outputs by `(source hash, analysis profile, engine version, dependency fingerprint)` only; a different tolerance, kernel version or unit decision is a different result. Capture stage timings and resource high-water marks without geometry content. Benchmark on all target OSes and representative fixtures before selecting defaults.

## Explicit limitations

The engine estimates geometry facts and candidates, not drawing intent or production-safe tool motion. A successful import is not validation of customer requirements. Healing, tessellation, stock envelopes, local thickness and tool access are tolerance- and algorithm-dependent. “No warning” is not a guarantee. See the canonical data semantics in `../02-domain/geometry-analysis-model.md`.
