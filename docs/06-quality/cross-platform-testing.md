# Cross-Platform Testing

> **Last updated:** 2026-08-12

> **Dependencies:** Platform spikes  
> **Supersedes:** None

The CI matrix targets current supported Windows x86_64, macOS arm64/x86_64 as policy determines, and Linux x86_64. Core Rust tests share one contract while retaining platform-specific evidence where primitives differ. Manual run 31555774851 adds Ubuntu 24.04 x86_64 exact OCCT construction, runtime assembly/host verification, internal dynamic-link closure, and configured desktop-host smoke evidence under the Linux parser filter. The Windows x64 workflow pins Visual Studio 2022/x64 plus canonical OCCT install directories, fingerprints runtime DLLs, keeps them app-local beside the worker, and requires x64 PE plus complete OCCT import-closure inspection before the same configured smoke. Run 31609710986 passes strict construction, all 11 adapter and 16 worker/process tests, and manifest-bound runtime assembly/re-verification. Its next gate fails closed because mixed `dumpbin /HEADERS /DEPENDENTS` output violates the strict standalone dependency grammar; the checker now calls the two documented modes separately and retains both x64 and import-closure validation. Both native workflows upload no binaries and do not exercise a window or package; the separate Debian workflow contains no native runtime. macOS hard memory and hostile-descendant escape prevention, macOS/Windows parser egress denial, Windows hard file-write bytes, general filesystem confinement, Linux aarch64 native behavior, completed Windows native evidence, and native-integrated interactive Linux GUI/package behavior remain explicitly unsupported or unproven rather than inferred from another platform's result. Native geometry, WebView, GPU, font, file-dialog, printing/PDF, HiDPI, path/Unicode, long-path, permission, backup, process-crash, package/install/uninstall, signing, and update behavior require platform-specific integration evidence.

Use deterministic headless tests where possible plus physical/virtual smoke systems. Record OS, architecture, GPU/backend, WebView/runtime, locale, scale factor, and package type with failures. A green core build does not prove packaging or viewport viability.

The opt-in `Linux Desktop Package Evidence` workflow adds a deliberately narrower Ubuntu 22.04 x86_64 Debian-package gate. It builds with pinned developer tools, inspects and privately extracts the package without publishing it, and requires the exact Debian-contained desktop executable to remain alive for a bounded virtual-display smoke. Initial run 31610449968 produces the Debian package but stops in the requested AppImage phase; that phase also fetches moving helper inputs, so AppImage is deferred until exact sources/hashes are governed. The config names the exact reviewed icon files and the corrected workflow targets Debian only. Run 31612819644 passes the complete extracted-payload gate in 15m40s at `b6d6ecd`, recording the amd64 Debian metadata plus package/executable hashes and the expected ten-second survival. The external native runtime is absent, and the session reports unavailable accessibility/desktop-portal services, so this proves package construction, contained-executable integrity, and shell-process startup only—not STEP analysis, native-dialog/portal behavior, physical display/GPU behavior, signing, installation, or supported-distribution compatibility. See [Linux desktop package validation](linux-desktop-package-validation.md).
