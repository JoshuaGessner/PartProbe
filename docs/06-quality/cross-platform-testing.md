The CI matrix targets current supported Windows x86_64, macOS arm64/x86_64 as policy determines, and Linux x86_64. Core Rust tests share one contract while retaining platform-specific evidence where primitives differ. Manual run 31555774851 adds Ubuntu 24.04 x86_64 exact OCCT construction, runtime assembly/host verification, internal dynamic-link closure, and configured desktop-host smoke evidence under the Linux parser filter. Windows run 31613259785 adds the equivalent Windows Server 2022/Visual Studio 2022 x64 construction, all 11 adapter and 16 worker/process tests, manifest-bound runtime assembly/re-verification, 24-binary/23-OCCT-family x64 PE closure, and configured STEP-to-USD-702 host smoke. Linux native-package run 31624958771 adds an unsigned extracted Ubuntu 22.04 Debian payload with verified package-resource runtime/link closure, retained STEP-to-USD-702 analysis, and bounded Xvfb launch; a bounded exact-payload native-picker/analysis interaction gate is under final validation. All native workflows upload no binaries. macOS hard memory and hostile-descendant escape prevention, macOS/Windows parser egress denial, Windows hard file-write bytes, general filesystem confinement, Linux aarch64 native behavior, Windows interactive GUI/package behavior, and broader Linux portal/Orca/physical-display behavior remain explicitly unsupported or unproven rather than inferred from another platform's result. Native geometry, WebView, GPU, font, file-dialog, printing/PDF, HiDPI, path/Unicode, long-path, permission, backup, process-crash, package/install/uninstall, signing, and update behavior require platform-specific integration evidence.

Use deterministic headless tests where possible plus physical/virtual smoke systems. Record OS, architecture, GPU/backend, WebView/runtime, locale, scale factor, and package type with failures. A green core build does not prove packaging or viewport viability.

The opt-in `Linux Desktop Package Evidence` workflow adds a deliberately narrower Ubuntu 22.04 x86_64 Debian-package gate. It builds with pinned developer tools, inspects and privately extracts the package without publishing it, and requires the exact Debian-contained desktop executable to remain alive for a bounded virtual-display smoke. Initial run 31610449968 produces the Debian package but stops in the requested AppImage phase; that phase also fetches moving helper inputs, so AppImage is deferred until exact sources/hashes are governed. The config names the exact reviewed icon files and the corrected workflow targets Debian only. Run 31612819644 passes the complete extracted-payload gate in 15m40s at `b6d6ecd`, recording the amd64 Debian metadata plus package/executable hashes and the expected ten-second survival. The external native runtime is absent, and the session reports unavailable accessibility/desktop-portal services, so this proves package construction, contained-executable integrity, and shell-process startup only—not STEP analysis, native-dialog/portal behavior, physical display/GPU behavior, signing, installation, or supported-distribution compatibility. See [Linux desktop package validation](linux-desktop-package-validation.md).

The separate `Linux Native Desktop Package Evidence` gate joins the exact OCCT construction and verified fixed resource-directory runtime with that extraction boundary. Run 31624958771 passes the complete combined checkpoint: it verifies the packaged runtime and all 23 OCCT dependency families before and after bundling, completes the real packaged-resource retained STEP-to-USD-702 smoke, and launches the exact extracted payload without a runtime override. The follow-on interaction step drives that same payload through exact AT-SPI targets, real keyboard input, and the host-owned GTK chooser without coordinate or source-path bypass; its final semantic-selection/Open-action run remains pending. The package remains unsigned, uninstalled, and synthetic-fixture-only, so no portal/Orca/physical-display or supported-distribution claim follows.
