## Checkpoint

The stacked TASK-004 comparison slices implement path-free ASCII/binary STL and 3MF analyzers, a persisted Core-unit corpus, bounded model-level Core metadata evidence, twenty-one persisted adversarial 3MF rejection contracts, and four persisted malformed binary-STL rejection contracts in `partprobe-geometry-import`. Callers provide an already-authorized byte slice plus explicit positive limits; no analyzer opens a source path or mutates application state. The STL entry point selects binary only when the 80-byte header, little-endian triangle count, and exact 50-byte record length agree; otherwise it applies strict ASCII grammar. STL parsing remains dependency-free. The 3MF path pins `quick-xml 0.41.0` and `zip 8.6.0` with ZIP defaults disabled and only Store/Deflate enabled; the dependency rationale and active graph are recorded in `../07-delivery/dependency-record.md`.

Versions `partprobe-ascii-stl-spike-v1` and `partprobe-binary-stl-spike-v1` produce provisional mesh evidence for:

- ASCII grammar or exact binary record framing identified from content and representation identified as mesh;
- unresolved/unknown source units requiring explicit confirmation;
- triangle count, axis-aligned extents, and surface area in source-coordinate units;
- undirected-edge manifold and watertight classification;
- paired-edge winding consistency; and
- enclosed volume and centroid only when the mesh is watertight, consistently wound, and has nonzero finite signed volume.

Binary records require exact framing, finite normal/vertex components, and a zero attribute field; unsupported per-facet attribute/color payloads fail closed rather than being silently discarded. Failures expose stable content-free diagnostic codes for invalid limits, input/triangle quota breaches, invalid text/structure/numbers, unsupported attribute data, degenerate triangles, and empty meshes. Non-finite intermediate measurements fail closed rather than entering evidence.

Version `partprobe-3mf-spike-v5` validates an in-memory ZIP/OPC package before reading the selected model. It requires the exact OPC content-types and root-relationships parts, resolves one internal StartPart target, verifies the model content type, and never extracts a part to disk. Preflight uses raw ZIP-entry access so name, type, encryption, sizes, ratio, and declared compression can be classified without first invoking a decompressor. It rejects encrypted, non-file, unsafe-name, duplicated/case-fold-ambiguous, externally targeted, unsupported-compression, malformed XML, document-type/general-reference, unsupported-required-extension, and unsupported-model-structure inputs. Limits cover original bytes, entry count, aggregate expanded bytes, per-XML bytes, compression ratio, vertices, triangles, objects, component references, and model-level metadata entries.

The v4-to-v5 change is a diagnostic-policy migration, not a geometry-calculation migration. Under v4, a ZIP method disabled in the dependency graph failed during decompressor construction and collapsed to `THREE_MF_INVALID_PACKAGE`; v5 inspects the raw header first and returns the already-defined `THREE_MF_UNSUPPORTED_COMPRESSION`. Accepted Store/Deflate packages, transforms, units, topology, and measurements are unchanged. No production or persisted customer analyses exist to migrate; preproduction callers must pin v5 for new results and must not relabel historical v4 failure records silently.

The bounded model contract accepts the 3MF Core namespace, every Core length unit plus its normative millimetre default, zero to the configured limit of unique well-known unprefixed model-level Core metadata entries, one leaf mesh object, zero or more bounded component objects that each contain exactly one reference to the immediately preceding object, and one build item targeting the last object. Component depth is therefore bounded by both `max_objects - 1` and `max_components`; no separate unbounded graph traversal exists. It enforces Core positive resource-ID bounds, uniqueness, and strict prior-object chain order. Vertices pass through every documented row-vector component transform from leaf to build, then the build transform, then canonical-millimetre conversion before entering the same format-neutral triangle measurement code as STL; this order follows the Consortium's [Core 1.4 model, metadata, matrix, component, and build rules](https://github.com/3MFConsortium/spec_core/blob/master/3MF%20Core%20Specification.md). Metadata text and names are never retained; evidence exposes only total and `preserve=true` counts and adds `THREE_MF_METADATA_NOT_INTERPRETED`. Evidence also distinguishes an explicit `unit` attribute from the Core default; retains leaf/build counts and IDs; represents component absence as an empty chain, not zero-like IDs; and retains every link's object ID, referenced ID, exact 12-value source-unit transform, and applied-state flag. Duplicate/unknown/vendor metadata, unsupported metadata attributes/types, object/item metadata groups, singular or reflected transforms, multiple references per component object, branching, non-immediate references, unions, extra/unused objects, multiple build items, materials, and unknown structures fail visibly rather than being flattened, unioned, interpreted, or ignored.

`FIX-MESH-014`–`038` turn twenty-five selected mutation-only checks into persisted input contracts. Each deterministic public input has a manifest hash and a typed schema-v1 recoverable-failure expectation that pins the exact content-free diagnostic and forbids geometry evidence or retained artifacts. These assertions exercise the in-memory comparison analyzers only; they do not claim the mesh path has entered the geometry worker, desktop application, containment boundary, or supported import flow.

The v3 algorithm identity deliberately supersedes v2 because accepting model-level metadata adds bounded evidence fields and a new warning while preserving geometry calculations. This is a preproduction comparison API with no persisted or customer analysis records. Callers must rebuild against the expanded positive-limit constructor and must not reinterpret old v1/v2 evidence as v3; no storage migration is required or implied.

## Evidence boundary

This is an internal comparison spike, not a supported importer. Binary evidence covers one simple zero-attribute analytic fixture plus four deterministic rejected derivatives. Successful 3MF evidence persists all six Core unit declarations plus the normative default, one project-generated translated direct mesh, one single-reference component variant, one two-link linear component variant, and one standard model-level metadata layout. Twenty-one rejected packages add selected graph, structural, metadata, extension, package, XML, and resource-limit evidence. Every input is derived from the same analytic cube, not independent geometry or CAD-tool evidence. Supported general component DAG/material semantics, alternate legal OPC layouts, broader malformed entity/geometry cases, and a representative malformed corpus remain absent. Metadata values are not interpreted as geometry, requirements, or estimating inputs. The spike does not recognize self-intersections, assign an authoritative mesh-confidence score, enter the geometry-worker/desktop flow, persist a model, or validate representative machining parts. Exact floating-point vertex identity is sufficient for these analytic fixtures but is not yet the reviewed production welding/tolerance policy. TASK-004 remains In Progress until the broader STL/3MF validity/failure matrix and acceptance evidence exist.
